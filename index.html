JARVIS (AI 음성 비서 / Python·LLM)

GitHub 보기

기간: 2026.10 | 역할: AI 에이전트(음성·LLM 명령 해석) 담당 / 팀 프로젝트 (5명)

  • 프로젝트 배경: 질문에 답만 하는 챗봇이 아니라, 말 한마디를 실제 PC 작업으로 연결하는 실행형 비서를 만들고자 함. 자연어를 그대로 OS 명령으로 실행하면 한 번 잘못 알아들었을 때 창을 전부 닫는 등 위험하기 때문에, '자연어 → 구조화된 도구 호출 → 허용 범위 검증 → 실행 → 결과 기록' 단계로 안전하게 연결하는 것을 핵심 과제로 삼음
  • 기술 초점: 규칙 우선 + LLM 보조 하이브리드 명령 라우팅, 허용 목록 기반 도구 실행
  • 주요 기여
    • 오프라인 Vosk로 호출어를 PC 안에서 감지하고, 호출 이후 명령만 클라우드 STT로 보내 비용과 음성 데이터 외부 전송을 줄임
    • 확실한 명령은 규칙으로 LLM 없이 처리하고, 여러 명령이나 앞 대화 참조만 LLM 도구 호출(도구 19개)로 넘기는 하이브리드 라우터 구현
    • 7개 유형 69개 발화의 평가 세트와 도구 호출·답변 품질 자동 채점 구축
    • 허용 목록 도구만 실행, 질문과 실행 분리, 강제 종료 대신 정상 종료(WM_CLOSE), 명시적 승인 후 고정된 WinGet ID로만 앱 설치 등 안전 장치 구현
    • CommandPlan(서버 계획)과 CommandResult(클라이언트 실행)를 분리하고, 실제 실행 전 상태를 저장해 볼륨·음소거 되돌리기 구현
  • 성과: LLM만 쓸 때 대비 정확도 88% → 91%, 평균 응답 2.15초 → 0.85초, 토큰 약 60% 감소 (평가 발화 69개) · CI 테스트 214개 통과
  • 기술 스택: Python, FastAPI, WebSocket, OpenAI API (gpt-4o-mini), Vosk, Google STT/TTS, Windows API, WinGet, GitHub Actions
문제 해결 / 배운 점

문제 해결

  • 호출어 놓침·오인식: 끝소리를 약하게 말하면 놓치고 비슷한 말에도 호출되는 문제. 진단 도구로 중간 결과 판정·글자 포함 검사·확신도 미확인이 원인임을 찾고, 확정 결과·단어 단위 일치·Vosk 단어 확신도 기준으로 판정 방식을 바꿈. 작은 마이크 입력은 소프트웨어 증폭으로 해결
  • 질문을 실행으로 오인: "메모장 켜져 있어?"가 '켜'라는 글자 때문에 앱을 새로 실행하던 문제. 상태 질문을 app_status로 먼저 분류하고 실행 판별을 그 뒤에 두어 질문에는 상태만 답하도록 수정
  • "조용히 해줘"의 모호함: PC 전체 음소거인지 자비스가 말을 멈추라는 뜻인지 모호한 문제. 자비스 TTS 응답 제어와 Windows 시스템 음소거를 분리해 한 표현이 PC 전체 소리를 끄는 오작동을 막음
  • LLM tool call 프로토콜 오류: 대화 이력에 tool 결과만 남고 이를 요청한 assistant의 tool_calls가 빠지면 OpenAI가 400 오류를 반환. LLM 전달 전에 역할 순서를 검증하고 짝이 없는 tool 메시지를 제외하도록 보완

배운 점

  • LLM은 기본값이 아니라 비용·지연·결과 변동이 있는 부품이라는 점을 배움. 확실한 명령은 규칙, 애매한 명령만 LLM에 맡기는 구조가 정확도·속도·토큰 모두에서 LLM만 쓰는 방식보다 낫다는 것을 직접 측정으로 확인함
  • "잘 된다"는 수치로 말해야 한다는 것을 배움. 쉬운 문장 40개에서 98%였던 정확도가 현실적인 발화에서는 77%로 떨어졌고, "할 일 전부 삭제해줘"를 그대로 실행하고 "완료했어요"라고 답하는 위험한 실패도 평가 세트 덕분에 발견함
  • 안전장치가 꼭 매번 묻는 방식일 필요는 없다는 것을 배움. 모든 실행을 확인받자 대화가 느려져서, 안전은 실행 방식(정상 종료, 허용 목록)과 사후 수단(알림, 되돌리기)으로 옮기고 확인 질문은 최소화함
  • 5명이 동시에 개발하는 환경에서 다른 팀원 코드를 고치지 않고 어댑터와 명세 기반 메시지로 연결하는 협업 방식을 익힘. 아직 연결되지 않은 기능은 가짜 성공 대신 [시뮬레이션]으로 표시해 결과를 정직하게 보고함

문제 해결

  • Dedicated Server FX: HasAuthority() 조건 분기로 서버의 공격 판정과 클라이언트의 시각 효과 실행을 분리해 공격 이펙트 중복 재생 문제 해결

  • Tile Occupancy: CombatManager가 이동 요청을 수집하고 요청 순서와 이동 속도 기준으로 승인, 대기, 재경로를 처리해 동일 타일 점유 충돌 해결

  • 다수 유닛이 동시에 판단하고 이동하는 전투 시스템에서는 개별 기능보다 시스템 간 책임 분리와 중앙 관리 구조가 중요하다는 점
